- 新增 cask `neriplayer`（`Casks/n/neriplayer.rb`）：上游 [cwuom/NeriPlayer-Desktop](https://github.com/cwuom/NeriPlayer-Desktop)（Tauri 2 + Vue 3 + Rust 的多源音乐播放器，arm64 / x64 两个 dmg）。
  - **本仓第一个「没法钉版本号」的 cask**。上游每构建一次发一条 release，tag 是 `NeriPlayer-<sha7>.<MMDDHHMM>`，产物名恒为 `NeriPlayer_1.0.0_<arch>-adhoc.dmg`（`1.0.0` 不变，真实构建标识只在 tag 与随包的 `build-metadata.txt` 里）。
  - 为什么不能按 README 的「优先补 livecheck」救：livecheck 必须返回整段 tag 后缀才能重建 URL，而 `Version` 按 sha 前缀排序这些字符串 —— 实测四个 tag，`ff9cfec.10102012`（旧）比 `c0947d5.10111750`（新）**大**，autobump 会静默漏升级；只取 `<MMDDHHMM>` 也不行（不带年份，跨年不单调）。结论：`version :latest` + `sha256 :no_check` + `/releases/latest/download/`，`brew outdated` 静默、无校验。
  - 校验值三源齐全（上游 `SHA256SUMS.txt` + GitHub asset `digest` + 本地 `shasum`，两架构全等），但一天就作废，未写进 cask。
  - 签名处置 **B**：`_CodeSignature` 在、`--verify --deep --strict` 退 0、`Signature=adhoc` + `flags=0x10002(adhoc,runtime)`、无 `Authority` / `TeamIdentifier=not set`、无公证票 → 清 quarantine，不进 LaunchAgent 列表。非沙箱（唯一 entitlement 是 `disable-library-validation`）；二进制里无 updater，故不设 `auto_updates`。
  - 下限 arm64 `11.0` / x86_64 `10.15`（plist 与 `minos` 一致），都在 Homebrew 下限及以下 → `depends_on :macos`（`:big_sur` 会被判 redundant，同 ferail；`audit_min_os` 读到 11.0 提前 return，这条检查没跑）。
  - `zap` 四条为**启动 + 退出**实测：`Application Support/NeriPlayer`（`neri_user_data.db` = 歌单/收藏/播放历史/曲库索引 + `secure/`）、`Application Support/moe.ouom.neriplayer.desktop`（settings/auth/sync json）、`Caches/moe.ouom.neriplayer.desktop`（27 MB WebKit）、`WebKit/moe.ouom.neriplayer.desktop`。**又验了一次 menumate 那条教训**：假 `HOME` 对 Rust 侧有效、对 WebKit 侧无效（Caches / WebKit 直接落真实家目录）。`Preferences` plist / `HTTPStorages` / `Logs/NeriPlayer` / saved state 两边都没出现，未列。
  - 环境限制（值得记）：本机终端里 Homebrew 内层 `sandbox-exec` 起不来（`sandbox_apply: Operation not permitted`），`brew install --cask` 与 `brew audit --online` 都会停在**解包**那一步 —— 所以 real install 与 `--online` 检查只能靠 `macos-26` 的 CI。本地能过的都过了：`ruby -c`、`brew style`（全仓 31 文件 0 offense）、`brew audit --strict` 退 0、`brew livecheck`（报 `neriplayer: latest`）、URL 直连下载 + sha256 三源对照。
