- 新增 cask `reinplayer`（Casks/r/reinplayer.rb）：上游 Ahurein/rein_player，Flutter 影音播放器（FlutterMacOS + media_kit/mpv），universal 二进制，v1.1.0。
  - token 原名想用 `rein_player`，查 `brew search` 无同名 core 公式冲突 → 用 `reinplayer`（文件名 ReinPlayer-v1.1.0.dmg，app 包是 `rein_player.app`）。
  - 关键判定：签名**自洽**（`codesign -v` / `--verify --deep --strict` 全包退 0、`_CodeSignature` 存在），但整体 **ad-hoc（无 Developer ID）** 且 `CFBundleIdentifier` 仍是占位 `com.example.reinPlayer`。
  - 实测 `brew install` 后 `/Applications/rein_player.app` 带 `com.apple.quarantine` → quarantine + 无 Developer ID 会让 Gatekeeper 首次启动拦「无法验证的开发者」。所以 Caveats 给 `xattr -dr com.apple.quarantine`（可选再 `codesign --force --deep --sign -`），**不进 LaunchAgent 列表**（其 verify 门能过 reinplayer，修不到 quarantine）。
  - 教训：之前草拟的「装完直接能开」是错的 —— 实测确认 Homebrew 给 cask 产物打 quarantine，ad-hoc 应用必被拦。README 表格 + 已知注意事项已改准。
  - 不设 `auto_updates`（ad-hoc 自更新不可靠）。zap 按 Flutter 的 bundle-id 规则列 `~/Library/{Application Support,Caches}/com.example.reinPlayer` + plist + Saved Application State。
  - 本机已 `brew install --cask reinplayer` 并清掉 quarantine，可直接启动。
  - CI（tests.yml）全绿：audit --strict --online 实测下载校验 dmg sha256，install/uninstall --zap 通过。
